# Relay Proxy 2.1

Relay направляет через один прокси-сервер (HTTP, HTTPS, SOCKS4, SOCKS5) только те программы и сайты, которые вы выбрали. Остальной трафик Windows идёт напрямую, системные настройки сети не меняются.

- **Приложения:** выберите EXE или найдите программу среди запущенных — её трафик пойдёт через прокси.
- **Сайты:** в браузерах через прокси открываются только домены из списка (с поддоменами); при вводе домена приложение подсказывает похожие.
- **Трей:** приложение живёт в трее и почти не тратит ресурсы, умеет запускаться вместе с Windows и подключаться само.
- **Один файл:** готовая сборка — один `RelayProxy.exe` со всем необходимым внутри; устанавливать ничего не нужно.

Готовый `RelayProxy.exe` — в разделе Releases. История изменений — в самом приложении, ссылка «что нового?» внизу боковой панели (код: `RelayProxy\Desktop\ReleaseNotes.cs`). При каждом выпуске версия в `RelayProxy.csproj` повышается и добавляется запись в `ReleaseNotes.cs`.

Трафик выбранных приложений перехватывается на уровне процессов и передаётся локальному мосту на базе sing-box. Общий TUN не создаётся: маршруты, адаптеры и DNS Windows не перенастраиваются. Невыбранные приложения проходят напрямую, без пользовательского TCP/UDP-туннеля Relay.

## Требования и запуск

Поддерживаются Windows 10 (версия 1809 и новее) и Windows 11, 64-разрядные. На Windows 10 приложение пропускает возможности, существующие только в Windows 11 (цвет заголовка и рамки окна), а вместо шрифта Segoe UI Variable использует Segoe UI. Скруглённые углы окна рисует само приложение, поэтому выглядят одинаково на обеих системах. Для перехвата процессов нужен .NET Framework 4.7.2 (в Windows 10 1803 и новее он уже есть). Сведения об ОС и режиме отрисовки пишутся в журнал при запуске.

Ядро, компоненты перехвата, сетевой драйвер и нужные библиотеки Visual C++ упакованы внутрь `RelayProxy.exe` (в исходниках — папка `engine`), ставить их отдельно не нужно. При первом включении Relay сам установит драйвер (нужны права администратора; иногда Windows просит перезагрузку). Сведения о компонентах — `engine\THIRD-PARTY.txt`.

Введите прокси, проверьте его и выберите EXE. При вставке `IP:порт` порт переносится в своё поле. Нажмите **Включить для приложений** и подтвердите права администратора. Перезапустите выбранные программы для новых соединений.

Relay использует собственную копию движка в `C:\Program Files\RelayProxy\ProcessRouter`. Уже установленные в системе похожие программы не изменяются и не запускаются; если такая программа уже активна, Relay сообщает о конфликте. Для собственной копии создаются два входящих правила брандмауэра, TCP и UDP, ограниченные её EXE. Брандмауэр не отключается.

В перехват включены выбранные полные пути и, при соответствующей опции, существующие EXE внутри разрешённой папки программы. Общие папки вроде рабочего стола и Program Files целиком не добавляются. Пакеты Microsoft Store учитывают обновление версии. Пустого правила «все приложения» нет. Локальная сеть проходит напрямую.

## Протоколы и задержка

HTTP и HTTPS работают через CONNECT; HTTPS дополнительно использует TLS до прокси с проверкой сертификата. SOCKS4 поддерживает TCP/IPv4 и User ID. SOCKS5 поддерживает TCP и, при поддержке сервера и включённой опции, UDP и IPv6.

UDP выбранных программ для HTTP/HTTPS/SOCKS4 и при выключенном UDP SOCKS5 направляется в локальный мост и отклоняется. Программы без TCP-альтернативы с таким прокси не заработают. Ping/ICMP через HTTP и SOCKS не передаётся.

У выбранных приложений задержка зависит от расстояния до прокси, его загрузки и пути до конечного сервера. Отсутствие задержки не гарантируется. Неизвестный владелец соединения остаётся на прямом маршруте; трафик через общие службы, защищённые процессы, античиты и WSL требует отдельной проверки.

Системный DNS остаётся обычным. Опция **DNS через прокси** относится к запросам, поступившим в локальный мост, а не ко всем запросам Windows. DNS браузера принадлежит самому браузеру. Первичное разрешение имени прокси sing-box выполняет напрямую через DoH.

## Интерфейс и хранение

Список приложений доступен для просмотра, поиска и прокрутки при подключении; изменение правил доступно после отключения. Настройки позволяют сворачивать окно в трей, запускаться при входе Windows, автоматически подключаться и уменьшать анимации. Автозапуск по умолчанию выключен и создаётся после сохранения соответствующей настройки.

Профиль: `%LOCALAPPDATA%\RelayProxy\profile.json`; пароль защищён DPAPI текущего пользователя. Настройки окна: `settings.json`. Пароль передаётся sing-box через stdin. Конфигурация перехватчика содержит пути приложений и локальный адрес моста, без пароля удалённого прокси. Журнал `relay.log` ротируется.

Оба движка принадлежат Windows Job Object и завершаются вместе с Relay. При обычном выходе перехватчик останавливается до локального моста. После остановки приложения возвращаются к обычному прямому подключению.

## Проверки

78 проверок настоящего sing-box и конфигураций: HTTP/HTTPS/SOCKS4/SOCKS5, авторизация, передача запроса, сертификаты, DPAPI, исключение невыбранных путей и отсутствие TUN в рабочем режиме. Реальный административный тест подтвердил: выбранный curl выходит через прокси, невыбранный процесс сохраняет исходный прямой IP, адаптеры/шлюзы/DNS остаются прежними. Интерфейс проверяется на переключатели, прокрутку, поиск, иконку панели задач и трей. UDP через удалённый SOCKS5 и каждое приложение отдельно не проверены.


## Сборка из исходников

Нужен .NET SDK 10 для Windows x64. В репозитории нет SDK, пользовательских настроек и `sing-box.exe` (он скачивается скриптом).

```powershell
.\scripts\get-engine.ps1
.\scripts\build.ps1
dotnet run --project tests\RelayProxy.Tests.csproj -c Release
dotnet run --project ui-tests\RelayProxy.UiTests.csproj -c Debug
```

`get-engine.ps1` загружает фиксированный релиз sing-box и проверяет SHA-256 архива. `build.ps1` собирает один автономный файл `outputs\RelayProxy\RelayProxy.exe`. Шейдер стекла (`Desktop\Glass.fx`) пересобирается скриптом `compile-shader.ps1`, для него нужен `fxc.exe` из Windows SDK; готовый `Glass.ps` уже лежит в репозитории.
